Discord Rich Presence on Linux: X11, Wayland, Hyprland, Sway

Discord Rich Presence works on Linux with Better Rich Presence, which detects your focused window on X11, GNOME Wayland, Hyprland, and Sway, and falls back to a process scan when none of those backends is available. Install the .deb, .rpm, or .AppImage from the latest release, keep the Discord desktop app open, and your status updates on its own. It is free, open source (MIT), and needs no Discord Developer Portal setup.

Supported desktop environments

Better Rich Presence reads the focused window through the backend that fits your session. The table lists what each environment uses for detection and for idle time, so your status updates when you step away.

Environment Detection and idle backend
X11 Active window hints (_NET_ACTIVE_WINDOW). Idle through Mutter or xprintidle.
GNOME Wayland Focused Window D-Bus (preferred) or the Window Calls GNOME Shell extension. Idle through Mutter IdleMonitor.
Hyprland and Sway Native compositor IPC through hyprctl and swaymsg.
Anything else Process-scan fallback that matches your enabled rules by priority.

Install on Linux

Open the latest release on GitHub and download the package that fits your system. Linux builds ship in three formats:

  • .deb
  • .rpm
  • .AppImage

Make sure the Discord desktop app is running, then start Better Rich Presence. When it reaches Discord, the colored band at the top of the window reads Live on Discord. Open an app from the catalog and check the Now tab, where the What friends see preview mirrors your Discord card.

GNOME Wayland details

On GNOME Wayland the app prefers Focused Window D-Bus. If that is not available, it can use the Window Calls GNOME Shell extension instead. Idle detection goes through Mutter IdleMonitor.

Hyprland and Sway need none of this They are detected through their own tools, hyprctl and swaymsg, so the GNOME options above do not apply to them.

The process-scan fallback

If no focused-window backend is available, the app switches to a process scan. It looks at the processes that are running, matches them against your enabled rules, and uses their priority order to choose what to show. Catalog entries list Linux process names alongside the Windows ones, so common apps are matched without setup.

In this mode the order of your list matters. Open the Apps tab, use Priority List mode, rank the apps you care about, and switch off the ones you never want shown. A missing app can be added: see the custom app guide.

Choose what Discord shows

Once detection works, the Apps tab controls the result. Dynamic mode follows the window you are using, and Priority List mode keeps your highest-ranked running app on your profile. You can switch any app off and customize the details and state text per application. For code editors, the app also reads the open file name from the window title to pick a programming language icon, so keep the file name visible in the title.

Tray menu and autostart

Linux builds include a system tray menu to reopen or quit the app, and XDG login autostart. Turn on Start on login in Settings and the app launches in the background with the --minimized flag, so it sits in the tray instead of opening a window.

Build from source

Prefer to build it yourself? You need Bun (or Node.js 18+), Rust, and the Tauri v2 system libraries for Linux, such as libwebkit2gtk-4.1-dev and libayatana-appindicator3-dev, as listed in the Tauri prerequisites. Run the app in development: 

git clone https://github.com/Joao-Camilo-Mallmann/Better-Rich-Presence-For-Discord.git
cd Better-Rich-Presence-For-Discord
bun install
bun run tauri dev

To produce the .deb, .rpm, and .AppImage packages:

bun run tauri build --config src-tauri/tauri.linux.conf.json

Troubleshooting

The status band at the top of the app shows what is going on.

Band says What to do
Live on Discord Connected and sharing. Check the Now tab for the preview.
Sharing off Turn the Share switch back on.
Paused for a game Discord detected a game and the app yields to it.
Connecting to Discord or Not connected to Discord Start or restart the Discord desktop app.

If the connection is fine but the wrong app shows, you are probably on the process-scan fallback: check the order of your Priority List. On GNOME Wayland, confirm that Focused Window D-Bus or the Window Calls extension is available. To report a bug on your desktop, open an issue on GitHub.

FAQ

Which Linux desktops does Discord Rich Presence work on?

Better Rich Presence supports X11, GNOME Wayland, Hyprland, and Sway for focused-window detection. When none of those backends is available, it uses a process-scan fallback that matches your enabled rules by priority.

Which Linux packages are available?

Linux builds ship as .deb, .rpm, and .AppImage packages. You can also build them from source with the Linux Tauri config in the repository.

Does it work on GNOME Wayland?

Yes. It prefers Focused Window D-Bus and can use the Window Calls GNOME Shell extension instead. Idle detection uses Mutter IdleMonitor.

Can it start automatically when I log in on Linux?

Yes. Turn on Start on login in Settings. Linux builds support XDG login autostart and launch minimized to the system tray.

Do I need a Discord Developer Portal application or a token on Linux?

No. Better Rich Presence connects to your local Discord desktop client over Discord IPC, with no Developer Portal setup, no token, and no account.
